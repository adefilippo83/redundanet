RedundaNet 3.0.0 is out

Community encrypted backup

Your backups are encrypted on your device, split with erasure coding and placed on other members' disks. A weekly restore test proves they come back. Repair runs without you.

Download 3.0.0 Join the network How it works

What you get

Backup run by the people who use it, with the guarantees spelled out

🔒

Encrypted on your device

Every object is encrypted with a key derived from your member secret and the content. Nobody else can read it, not the hub, not other members.

📚

Erasure coded across members

Each object is split k-of-n, today 2-of-3 on the live network, and the shares go to other members' storage servers. The split is set by the signed manifest and can change through a declared transition.

📅

Daily backups, weekly restore tests

A backup set is one or more folders. The agent scans them daily. Every week a restore test reads a sample back and compares it to the source.

🔧

Repair without the owner

Storage servers scrub their shares monthly. The hub schedules repair of under-placed objects without involving the owner, and the status page shows it.

⏬

Restore a file, a folder or a snapshot

Snapshots are kept by a retention policy. Deleted data stays recoverable for 30 days.

⚙

One static binary

One program named redundanet, written in Go. No containers, no Python, no Docker. It updates itself from a signed release index.

1

Identity from a 12-word phrase

redundanet identity init shows a twelve-word phrase once. Your member key (Ed25519) comes from it. Every device gets a certificate signed by the member key.

2

A signed manifest

Member and storage lists live in a manifest in the GitHub repository, signed offline by the maintainer's operator key. Agents fetch it every five minutes and apply a newer signed revision at once.

3

A hub for rendezvous and relay

The agent reaches the hub outbound. Devices connect to each other directly through hole punching when they can, otherwise through the hub's relay. No inbound firewall rule needed.

4

QUIC with TLS 1.3

Devices authenticate each other over QUIC with TLS 1.3, by their device keys. A storage node may forward a UDP port to be reached directly more often.

5

Self-update with probation and rollback

The agent checks the signed index hourly, downloads, verifies the hash, runs the new version in probation for up to two minutes, keeps the old binary as redundanet.old, and rolls back by itself if the new one does not reconnect.

Platforms

Linux, macOS and Windows, one static binary each

Tested on Linux (x86-64 and ARM64, including Raspberry Pi 5) and Apple silicon Macs. Windows and Intel Mac builds are provided and pass the test suite, but have not run on the live network yet.

What is not there yet

The limits of 3.0.0, stated plainly

  • One hub, on a bare IP address. With it down there are no new connections, no repair scheduling and no status page; existing direct connections continue. The public status page is hosted on the fly.io app of the old product.
  • No OS keystore.
  • Windows and Intel Mac builds have not run on the live network yet. Raspberry Pi 4 is not measured.
  • The RedundaNet 2 wind-down is manual.

Join in three steps

You need a GitHub account. Contributing disk is welcome, not required.

1

Install and create your identity

One line installs the agent on your laptop; one command creates your identity, installs the service and opens the join form filled in. The phrase is shown once; write it down. The network is built in: nothing to paste.

curl -fsSL https://redundanet.com/install.sh | sh
redundanet setup
2

Prepare a storage node, if you contribute disk

A Linux machine with at least 10 GiB free. One line on the node and one command on your laptop pair it and give you its device key for the form.

Storage node setup →
3

Send the join request

The form opens a GitHub issue. A workflow validates it and opens a pull request; the maintainer signs the manifest offline and merges. Every agent applies it within five minutes, and your devices are in.

👁 Privacy

The project collects nothing: no accounts, no analytics, no telemetry. This site stores only your language choice in your browser. The policy lists exactly what the software sends, and to whom.

Read the privacy policy →

🔑 Code signing

Windows signing through SignPath and macOS notarization are set up in the release workflow but not yet active (accounts pending); until then every binary is unsigned and the signed release index is the way to verify a download on every platform. Linux binaries are never code-signed; the index covers them.
