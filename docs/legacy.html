RedundaNet 2, the legacy product

The grid that came before RedundaNet 3. It ended on 13 November 2026.

Ended. RedundaNet 2 stopped on 13 November 2026, when its hubs were shut down. The old grid can no longer be read or written. Nothing was deleted on members' nodes: each member retires their own stack and deletes the old shares when they choose. New members join RedundaNet 3; former members follow the migration guide.

What it was

RedundaNet 2 was a Python command line tool and a Docker Compose stack. Nodes joined a tinc mesh VPN; GPG keys were the node identities and doubled as the tinc keys; a YAML manifest on GitHub was the source of truth for membership; files were stored with Tahoe-LAFS, erasure coded 2-of-4 across the storage nodes; a hub on fly.io relayed peers behind NAT, ran the Tahoe introducer and served the public status page.

Six members and eight storage nodes were on it at the end. The Python package redundanet on PyPI (2.7.40 was the last version) was its command line tool.

Documentation

The RedundaNet 2 code, containers and documentation are no longer in the repository. They are in its history: the tree at the tag v2.7.40, the last release.

Why RedundaNet 3

RedundaNet 3 replaces the Docker stack, the VPN and Tahoe with one static binary: identity from a phrase instead of GPG keys on keyservers, a signed manifest, a hub for rendezvous and relay, QUIC with TLS 1.3 between devices, erasure coding across members, weekly restore tests, repair without the owner and self-update with rollback. The home page says what it does; the architecture page says how.
