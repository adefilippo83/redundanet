Join the network

A join request is a GitHub issue. The form below builds it in your browser; nothing leaves this page until you open the issue on GitHub.

⚙ Before you fill the form

  1. Install the agent on your laptop and run setup. It creates your identity (the phrase is shown once; write it down), installs the service and opens this form with your member key (52 characters) and your storage node already filled in. The network is built into the binary: nothing to join by hand. 
    curl -fsSL https://redundanet.com/install.sh | sh
redundanet setup
  2. If you contribute disk, prepare your storage node first so you have its device key. Pick a name for it (lowercase letters, digits and hyphens).
  3. You need a GitHub account. Your GitHub login, lowercased, is your member name unless you choose another lowercase name.
  4. A RedundaNet 2 member also makes the legacy attestation; see the migration guide.
  5. Already a member, adding a storage node? Pair it from your laptop, then redundanet join-request opens this form in that mode with the node's certificate as proof; or choose that case below and paste the certificate the node prints with identity show --certificate.

📋 Member rules

  • Names are lowercase letters, digits and hyphens.
  • A member who contributes disk lists at least one storage device. A storage node needs at least 10 GiB free above its floor.
  • A member without a storage device needs contribution_gb: 0 with an allocation_gb and a sponsor (another member or the reserve), which the maintainer sets.
  • Your allocation is derived from your contribution and the encoding overhead; redundanet validate --manifest manifests/manifest.yaml prints every member's allocation.
  • Your member name and member key become part of the public manifest and stay in the repository's history forever. See the privacy policy.

The node's certificate

The proof that the node is yours. redundanet join-request on the laptop that paired it fills it in; sudo /var/lib/redundanet3/bin/redundanet identity show --certificate on the node prints it. The workflow checks that your member key signed it for this device with the storage role.

The button opens a prefilled issue on GitHub. If it does nothing, your browser has JavaScript off: open a new issue by hand with the title [Join Request] Member: <name> and the table described in docs/join.md.

⏳ What happens after

  1. A workflow validates the request and opens a pull request adding you under members: (name, key, contribution, join date, status active, and the legacy PGP attestation when given) and your node under storage: (member, device, name, UDP port when given), raising the manifest revision by one.
  2. The maintainer reviews, signs manifest.sig offline with the operator key, and merges.
  3. Every agent applies the new revision within five minutes. Your devices are admitted from then on.
  4. Add a backup set; the service setup installed runs it daily: 
    redundanet backup add NAME FOLDER

The long form: docs/join.md. Your node appears on the status page under your name.
