Install

One line installs the agent and opens its page in your browser; the page makes your identity and sends you to the join form. A Linux storage node is one line and a pairing code. Then your first backup set.

One line

One line finds your platform, downloads the newest release, checks it against the signed release index, installs it, starts the agent as a service that runs at login, and opens the agent's page in your browser. The page walks you through the rest. In a terminal on macOS and Linux, in PowerShell on Windows:

# macOS and Linux
curl -fsSL https://redundanet.com/install.sh | sh

# Windows, in PowerShell
irm https://redundanet.com/install.ps1 | iex
  • The page asks which case you are in: new here (a twelve-word phrase, shown once, then three of its words asked back), your recovery phrase at hand, or another device of yours nearby to pair with. Then it becomes the device's page: it says whether you are listed in the manifest yet and links to the join form filled in from this device until you are. The phrase appears only there, on a page served on 127.0.0.1 and reached through a one-time link. Prefer a terminal? redundanet setup walks you through the same steps.
  • The scripts are docs/install.sh and docs/install.ps1 in the repository, short enough to read first. Each refuses a download whose sha256 or size differs from the signed index, puts the binary in your data directory where the agent can update it, puts it on your PATH (a link at /usr/local/bin/redundanet on macOS and Linux, the one step that asks for your password; the folder added to your user PATH on Windows, with nothing to approve), and has the installed binary check the index's signature itself.
  • The network is built into the binary: its name, its hub, the operator keys and where the signed manifest is served. Nothing to paste and no flag to type; the agent fetches the manifest the first time it needs it.
  • The phrase. redundanet identity init shows a twelve-word phrase once and never again. Write it down and keep it like a password: your member key comes from it, and so does every device you certify. There is no reset. --passphrase seals the identity file on disk.
  • In the join form it opened, add your member name and your contribution, then open the issue on GitHub; your devices are admitted once the maintainer has signed the manifest with you in it, and redundanet status says so.
  • This page is the short form. The long one, with every option and the way by hand, is docs/install.md on GitHub.

macOS

Apple silicon is tested on the live network; the Intel build passes the test suite but has not run there yet. The one line above installs it and opens the page; the service is a launchd agent that starts at login.

  • Full Disk Access. A service that backs up Documents, Desktop or Downloads needs Full Disk Access for the agent. backup add says so when a folder is guarded: grant it to redundanet in System Settings, Privacy & Security, then run the backup again. Granted once, it stays: the service runs the agent through a launcher that never changes, so macOS does not ask again after each update.
  • Notarization is not active yet. A copy the script fetched carries no quarantine mark and runs at once; one a browser downloaded makes macOS ask you to allow it under Privacy & Security first.
  • Data directory: ~/Library/Application Support/redundanet; the binary is in its bin.

Windows

The Windows build passes the test suite but has not run on the live network yet. The one line above, in Windows PowerShell 5.1 (every Windows 10 and 11 has it) or PowerShell 7, needs no administrator rights: the binary goes to bin\redundanet.exe in your data directory, that folder joins your user PATH (terminals opened from then on find redundanet), the service is a logon task that restarts on failure, and the page opens. By hand instead: the zip from the download page, its sha256 checked as that page shows, the folder on your PATH, then two commands in a terminal.

redundanet service install
redundanet open
  • The binary is not code-signed yet, so Windows may warn before it runs. The script checks the sha256 against the signed index for you; a zip taken by hand, check yourself first.
  • A OneDrive online-only file is listed as skipped, "not on this computer", never pulled down.
  • Data directory: %AppData%\redundanet; the binary is in its bin.

Linux laptop or desktop

x86-64 and ARM64 are tested on the live network, including Raspberry Pi 5. For a machine you sit at: the one line above, then the page. The service is a systemd user unit that starts at login and keeps running when you log out.

  • Data directory: ~/.config/redundanet; the binary is in its bin.
  • For a headless machine that contributes disk, use the storage node flow below instead.

Linux storage node

A Raspberry Pi can skip the steps below: each stable release carries a ready-to-boot image with the agent installed as a storage node. Flash it, boot it, pair it from a device of yours with the code it leaves on the SD card, and give it a disk labeled REDUNDANET, which it mounts on its own. The guide is rpi-image/README.md.

A storage node is a Linux machine, usually headless, that holds other members' shares. It runs the agent as a system service under its own user, and it never holds your phrase: a device of yours certifies it through a one-time code. One line as root on the node, one command on your laptop, on the same network or anywhere: the hub relays the exchange when the two cannot reach each other.

1. On the node: install

curl -fsSL https://redundanet.com/install.sh | sudo sh -s -- --node /mnt/storage

The same download and checks, then redundanet node install: it creates the service user, the directories and the unit, puts the binary in place and shows a pairing code. /mnt/storage is the disk you contribute, mounted; the share store goes in its redundanet3 directory, and a path that is not a mount point is refused, so shares never land on the system disk. A storage node needs at least 10 GiB free above its floor.

2. On your laptop: pair

redundanet device pair --storage <code>

With your phrase, your laptop certifies the node through the code and hands it the network. The node starts by itself, and your laptop remembers it, so redundanet setup or redundanet join-request puts its key and name into the join form; the node prints its storage: lines too. It counts once the maintainer has signed the manifest with them.

No laptop of yours at all? The runbook's script makes the same layout with a certificate file copied over SSH.

  • Layout: data in /var/lib/redundanet3, the binary at /var/lib/redundanet3/bin/redundanet, service user redundanet3, unit redundanet-agent, settings in /etc/redundanet3/agent.env (NETWORK, CHANNEL, STORAGE_PATH).
  • Use the full path /var/lib/redundanet3/bin/redundanet in commands on a node. On a RedundaNet 2 node the Python redundanet on PATH is the legacy tool.
  • No inbound firewall rule is needed. A node may forward a UDP port and list it in the join request as udp_port to be reached directly more often.
  • The local page over SSH: ssh -L 4470:127.0.0.1:4470 node, then sudo /var/lib/redundanet3/bin/redundanet open --print.
  • The runbook: agent/deploy/node/README.md.

First backup

Once your devices are admitted (the maintainer has merged your join request), add a backup set: a name and one or more folders. The agent scans it daily and runs a restore test weekly.

redundanet backup add NAME FOLDER [FOLDER...] [--exclude a,b]
redundanet backup list        # sets, last runs, skipped files by reason, restore tests
redundanet backup run [NAME]  # a run now, instead of waiting for the daily one
redundanet backup verify      # a restore test now; the result shows in backup list
  • Snapshots are kept by the retention policy in backup.yaml in the data directory, edited by hand. Deleted data stays recoverable for 30 days.
  • backup remove NAME drops a set. backup cleanup [--dry-run] [--force] runs the cleanup now; it also runs weekly on its own.
  • The member guide: docs/backups.md.

Restore

Restores are per file, folder or snapshot, from any device of yours, into a directory you name.

redundanet restore list                                   # your devices and their snapshots
redundanet restore browse DEVICE SNAPSHOT [PATH]          # look inside without fetching
redundanet restore start DEVICE SNAPSHOT [PATH] --to DIR [--overwrite]
redundanet restore status

Everyday commands

redundanet status [--json]          # what the running agent sees
redundanet open                     # the local page, 127.0.0.1:4470, through a one-time link
redundanet logs [-n 100]
redundanet network status [--refresh]
redundanet service status | uninstall
redundanet update check | apply | status
redundanet diagnostics [--out FILE] # a bundle with no paths, URLs or addresses, to send by hand
redundanet device revoke --device KEY   # a lost device: prints a signed revocation for the manifest
redundanet version
  • device revoke runs on any device of the member and asks for the phrase. The record goes into the manifest under revocations:; the operator signs and merges, and every agent and server refuses the device from then on.
  • Every command: docs/cli.md.

Where things live

WhereData directory
macOS~/Library/Application Support/redundanet
Linux~/.config/redundanet
Windows%AppData%\redundanet
Linux storage node/var/lib/redundanet3, share store in STORAGE_PATH/redundanet3

The local page and the command line talk only to the agent on the same computer, on 127.0.0.1:4470, never on the LAN. Nothing is uploaded anywhere by itself. See the privacy policy and docs/configuration.md.
